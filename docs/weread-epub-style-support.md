## 测试方法

自造一本 17 章、78 个探针的样张 EPUB（随仓库附带 `epub/weread-epub-style-specimen-1.0.epub`，生成源码见 `build/`），导入微信读书后逐屏截图、逐条判读渲染结果，关键歧义处（缩进、生僻字、浮动）做像素级测量与放大复核；「章末注角标点击跳转」另做一次真机交互测试。

## 一、三条全局结论

1. **外部 `style.css` 会被解析，但生效粒度很粗。** 无样式基准页与各带样式页差异巨大，证明样式表被正常吃进；但引擎只稳定认「扁平单类名」这一种写法——后代选择器、伪类/伪元素、`@media` 都不可靠，连**内联 `style` 属性都会被拆掉**。

2. **首行缩进（`text-indent`）与行距（`line-height`）被 App 全局设置接管，CSS 写了也白写；正文字体（`font-family`）走内置字体识别（白名单式）**——未知的字体名与系统字体名（Kaiti SC 等）都回退全局设置，但第三方 EPUB 里常见的字体栈（汉仪楷体S 打头）其楷体名可生效（见 §4 字体）。

3. **"结构型"元素基本全活且质量可接受，死区集中在三处。** 标题阶梯、列表全家、表格全家、代码块、引用块、图片等比缩放、上下标、链接、emoji 均可用；明确死区是**硬分页**（只能靠拆 spine 文件）、**EPUB3 弹注**与**章内锚点跳转**（点角标无反应）。

## 二、活 / 死 / 灰区清单

### ✅ 活（可放心使用）

- 扁平单类名的：`background`、`color`、`font-size`（相对单位）、`text-align:center`（文字）、`letter-spacing`、`border`（实线 / 虚线 / 竖直灰线）
- 标题 `h1`–`h4` 的字号 / 字重 / 字距阶梯
- 列表全家：`ul` / `ol` 嵌套、中文序号（一 / 二 / 三）、悬挂缩进、`list-style:none`
- 表格全家：边框、表头、`caption`、`colspan`、12 列超宽表、单元格超长 URL
- `pre` 保留行首空格、行内 `code` 等宽灰底、`word-break:break-all`
- 图片按版心宽**等比缩放、不裁切**（含 3200×1200 超大图）
- `float + clear` 的语法层（文字让位、`clear` 换行）
- 链接（渲染正常，但章内锚点点不动，见 §8 脚注 / 弹注）、`sup` / `sub`、emoji（彩色）、全半角
- `hr`（细灰线）、`border-top` 画线、空段落留白
- `blockquote` 左灰竖线 + 缩进 + 灰化小字（显式写死的 `margin` / `padding` 生效）

### ❌ 死（直接进禁用表）

- `line-height`（被 App 全局行距接管，1.2 与 2.4 视觉无差别）
- `text-indent`（被 App 全局缩进接管，**连 `text-indent:0` 都被缩进**）
- `::first-letter`、`:nth-child`
- **内联 `style` 属性**（连内联都被拆，别指望它兜底）
- `page-break-after`、`break-inside`
- `@media`（无法在窄屏验证，视为不可依赖）
- `flex`（掉成上下堆叠）、`transform`、`text-shadow`
- `img` 的 `style` 定宽 / 限宽 / 定高（60% / 70% / 200px 均无效）
- `small-caps`；font-family 的**单一自造名与系统名**（汉仪楷体S 单独写、Kaiti SC 等）——见 §4 字体的白名单边界
- CJK 扩展 B 区生僻字（渲染成豆腐块）

### 🟡 灰区（一律回退扁平单类名）

- **后代 / 嵌套选择器**：时而只有 `color` 活、时而 `color + font-size` 都活，不稳定
- **`figure` 居中**：`figcaption` 文字居中活，但 `figure` 内的 `img` 靠左
- `float` 绕排：语法生效但被 float 的图片本体不渲染（右侧只剩空条）
- 竖版长图 / 超小图：能显示但靠左不居中，caption 位置异常

## 三、逐项边界

### 1. 首行缩进 —— ❌

EPUB 里的 `text-indent` 完全被 App 全局「正文首行缩进」接管。像素实测：2em 段与 `text-indent:0` 段的**首行左缘同为 224px**、续行 156px——连刻意顶格的对照段也被缩进。CSS 里写 text-indent 是浪费。

### 2. 行距与字距 —— 🟡 分裂

`line-height:1.2` 与 `2.4` 视觉几乎无差别 → **行距死**，被 App 全局「行距」接管。`letter-spacing:.25em` 明显拉开 → **字距活**。

### 3. 字号单位 —— ✅ 用相对单位

`em / rem / % / pt` 四档全部放大生效；`16px` 档与正文无异。→ **优先相对单位，别用 px**（px 会被当固定值压回正文大小）。

### 4. 字体 —— ❌

`font-family` 起初肉眼不可判，暂记「被覆盖」；**后续反证修正**：一份第三方 EPUB 的引语段使用一套以「汉仪楷体S」打头的字体栈 + `color:brown`，把这套栈搬到自制书里实测，同样渲染出楷体+棕色；而单独写汉仪楷体S、系统楷体名（Kaiti SC/STKaiti/KaiTi）都无效 → **font-family 是内置字体识别（白名单式），不是无差别覆盖**。`small-caps` 无效。

### 5. 图片 —— 🟡 有坑

常规图与超大图全部按版心宽等比缩放、不裁切、不撑破；但 `img` 的 `style` 定宽 / 限宽 / 定高均不生效，竖版长图与超小图**靠左不居中**、caption 位置异常；`float` 绕排时被 float 的图本体不渲染。→ **图片尺寸与位置在出图时定死，居中直接画进图片像素**。

### 6. 表格 —— ✅ 生产可用

边框、表头、`caption`、`colspan`、12 列超宽表、单元格长 URL 全部正常、不溢出（字号被压小）。→ **表格可直接走原生 HTML 路线**，不必为安全全改图片。

### 7. 分页 —— ❌ 只能拆文件

`page-break-after:always` 后直接接正文、不另起页；`break-inside:avoid` 未触发；同文件双 `h2` 不分页。→ **硬分页只有拆 spine 文件一条路**。

### 8. 脚注 / 弹注 —— ❌ 不能跳转、不能弹窗

**实测一**：`<a epub:type="noteref">` 渲染成 `[1]` 蓝色上标链接；`<aside epub:type="footnote">` 内容**平铺成普通段落**、不弹窗。→ **EPUB3 标准弹注不支持**。

**实测二**：自己写的章内锚点（正文 `<a href="#n1"><sup>[1]</sup></a>` + 章末 `<p id="n1">`，锚点双向可解析、无悬空）**真机点击完全无反应**。→ **章内锚点跳转同样不支持**。

机理旁证：微信读书 App 是自研 DTCoreText 排版引擎（非 WebView），对自制书的正文超链接交互支持有限；其自家脚注走 `qqreader-footnote` 私有实现、内部导航是「章」级私有协议 —— **商店书能跳 ≠ 自制书能跳**。

**不要依赖任何形式的注释跳转。** 推荐做法三条：

1. **短注用行内小字夹注**：`<span class="note">（注：……）</span>` 紧跟被注词，扁平单类名、小字号走 `em`。
2. **长注放章末，并接受它不可点**：正文角标只作视觉标记（`<sup>[1]</sup>` + 扁平类名），别写 `<a href>` 指望跳转。
3. **面向多平台发布时**，仍可写规范 `<aside epub:type="footnote">` 集中在章末 —— Apple Books / Kindle / 多看 / 静读天下会弹窗或跳转，微信读书里退化为章末注释、位置天然正确。

### 9. 引用块 —— ✅

左灰竖线（`border-left`）渲染出来，缩进 + 灰化小字都在，显式写死的 `margin` / `padding` 生效；嵌套引用块内外缩进层级可辨。但仍应改用扁平单类名实现。

### 10. 选择器 —— ❌ 只用扁平单类名

扁平单类名 ✅ 全活；后代选择器 🟡 `color` 活、`font-size` 死；`::first-letter`、`:nth-child` ❌；**内联 `style` 属性 ❌（本轮最反直觉的发现）**；`@media` 无法判定。→ **样式一律写成扁平单类名，且别指望内联 style 兜底。**

### 11. 危险元素与字符 —— ⛔ 黑名单

`display:flex` 掉成上下堆叠；`transform:rotate`、`text-shadow` 无效；emoji 彩色正常、全半角正常；**生僻字「𠮷」（CJK 扩展 B 区）= 豆腐块**。

### 12. 其他结构 —— ✅ 活

标题 `h1`–`h4` 四档阶梯整条可用；列表两级符号、中文序号、悬挂缩进、`list-style:none` 全活；裸 `hr` → 细灰线、`border-top` → 虚线、空段留白保留、`H₂O / 10⁸` 位移正确；`pre` 行首三空格保留、行内 `code` 等宽灰底。

## 四、给 EPUB 生产者的落地建议

### 4.1 六条铁律

1. **样式只写扁平单类名**；不用后代 / 伪类 / 伪元素 / `@media`，也别指望内联 `style` 兜底。
2. **文本缩进与行距交给 App 全局设置**，CSS 里别写 `text-indent` / `line-height`。
3. **字号用相对单位（em / rem / % / pt），别用 px**；`font-family` 不要依赖系统字体名或单一自造名——引语/注释区想换楷体，用一组可被识别的楷体字体栈（汉仪楷体S 打头）：`"汉仪楷体S","ETrump KaiTi","方正仿宋","FZFSJW--GB1-0","PingFang SC",-apple-system,"SF UI Text","Lucida Grande",STheiti,"Microsoft YaHei",sans-serif`（真机实测可渲染出楷体+棕色）。
4. **图片尺寸与位置出图时定死**，居中直接画进图片。
5. **表格可直接用原生 HTML**；**硬分页只有拆 spine 文件**；**弹注与正文锚点跳转都不支持** —— 短注用行内小字注入正文，长注放章末且不可点。
6. **黑名单**：`flex / transform / text-shadow / small-caps / CJK 扩展生僻字`。

### 4.2 禁用表（照抄进流水线）

| 禁止使用 | 原因 | 替代方案 |
| --- | --- | --- |
| `text-indent` | 被 App 全局缩进接管（连 0 都被缩） | 交给 App 设置 |
| `line-height` | 被 App 全局行距接管 | 交给 App 设置 |
| `px` 字号 | 被当固定值压回正文 | `em / rem / % / pt` |
| `font-family` 单一自造名 / 系统字体名 | 回退全局字体，无效果 | 引语换字体用该楷体字体栈整串（汉仪楷体S 打头） |
| 后代 / 伪类 / 伪元素 / `@media` 选择器 | 生效不稳定或完全失效 | 扁平单类名 |
| 内联 `style` 属性 | 会被拆掉 | 扁平单类名 |
| `img` 的 style 定宽 / 限宽 / 定高 | 不生效 | 出图时定死像素 |
| `figure` 居中 / `margin:0 auto` | 图不居中 | 居中画进图片 |
| `float` 图文绕排 | 被 float 的图不渲染 | 上下排列 |
| `page-break-after` / `break-inside` | 无效 | 拆 spine 文件 |
| `epub:type` 弹注 / 正文锚点跳转（`href="#id"`） | 注释平铺不弹窗；角标点击无反应 | 行内小字注 / 章末注且不做跳转 |
| `flex` / `transform` / `text-shadow` | 无效 | 普通块级 + 扁平类名 |
| `small-caps` | 无效 | 直接写大写 |
| CJK 扩展 B 区生僻字 | 渲染为豆腐块 | 避免使用或转图片 |

### 4.3 出书前自检清单

- [ ] 所有样式都是扁平单类名，且无内联 `style`？
- [ ] CSS 里已删除 `text-indent` / `line-height` / `font-family` / `px` 字号？
- [ ] 所有图片已按目标版心定好像素、居中画进图内？
- [ ] 需要硬分页处已拆成独立 spine 文件？
- [ ] 注释已全部改为行内小字注 / 纯视觉章末注，无 `epub:type` 弹注、且无 `href="#id"` 依赖跳转？
- [ ] 表格保留原生 HTML（而非无谓转图）？
- [ ] 全稿无 `flex / transform / text-shadow / small-caps`、无 CJK 扩展生僻字？
